= ADKM

*本地优先的 AsciiDoc 知识库* · Local-first AsciiDoc knowledge base

版本 `0.0.1` · 预发布 · 暂无已发布的安装包，源码可直接构建运行

ADKM 把 `.adoc` 与 `.md` 收进同一个本地库：一套索引、一套图谱、一套交叉引用校验，离线可用。它基于 link:https://github.com/AlexHercules/geode[Geode]（Apache-2.0）深度改造而成，不是 Geode 的发行版。

'''

== 为什么做这个

市面上的本地知识库都以 Markdown 为前提，因此都不理解 AsciiDoc 的语义。AsciiDoc 用户真正依赖的东西——属性别名、交叉引用、include 组装、条件包含——在 `\[[wikilink]]` 的世界里没有对应物。

ADKM 不是"给某个 Markdown 工具加一个 AsciiDoc 渲染器"，而是在笔记库式的界面里补上*文档工程的校验能力*：

[options="header"]
|===
|能力 |Markdown 工具 |ADKM
|引用 |`\[[Note]]`，按文件名模糊匹配 |`\xref:` 宏与 `\<<>>` 简写，含属性别名展开
|失效检测 |断链提示 |三态：有效 / 断链 / *未解析*（属性未定义、动态目标、include 越界）
|版本一致性 |无 |中英双语章节对齐、行数偏差
|组装 |无 |`include::` 归属与递归、环检测
|图谱 |笔记级关系 |文档级关系 + 组装关系
|===

== 现在能用的

* 打开本地文件夹作为 vault，Markdown 与 AsciiDoc 共用文件树、图谱、反链、大纲与搜索
* *纯文本 `.txt` 同索引*：正文可全文搜索、走既有文本编辑 / 阅读视图，可被 `\xref:` / `\link:` 按路径引用；txt 按无结构处理，不参与大纲 / 章节解析，不伪造标题层级
* 编辑器三模式：实时预览 / 源码 / 阅读，多标签与分屏
* *AsciiDoc 进索引*：`\xref:path[]`、`\<<path,text>>`、`\link:path[]`、`include::path[]` 四种写法都识别；文档头内的属性别名会求值，`\xref:{spec}[]` 能解析到真实文件
** 实测一份 130 篇 adoc / 220 条引用的真实语料：0 条未解析，全量索引 67 ms
* *AsciiDoc 阅读视图*：官方 Asciidoctor.js 浏览器构建渲染，标题、表格、admonition、代码块、目录均正确；按需动态加载（约 1.3 MB 独立 chunk，不拖慢首屏），`\xref:` 转成应用内可点链接
* *AsciiDoc 源码编辑*：源码模式下 `.adoc` 使用独立语言模式与语法高亮（标题、属性行 / `{attr}`、注释、`\xref:` / `\<<…>>` / `\link:` / `include::`、列表项、代码块）；`\xref:path#anchor[text]` 与 `\<<path,text>>` 可 Ctrl/Cmd+Click 跳转，目标不存在时给出提示而不报错；标题章节可按层级折叠，大纲面板按 adoc 标题层级展示并点击跳转源码行
* *文档体检*：失效 `xref` / `include::`、include 环、Antora 组件与版本资源 ID，并可按组件版本切换解析上下文
* *三态引用校验*：全库引用按有效 / 断链 / 未解析归类，独立「引用校验」面板列出所有非有效条目，按状态与格式筛选，点击跳转到对应源码行；图谱中断链边以虚线 + 独立配色标出，图例可辨
* *双语对齐*：识别 `foo.adoc` ↔ `foo-en.adoc` 配对，逐对比对版本号、标题层级分布、章节结构与行数偏差；并列树展示两边章节，缺失章节高亮，点击跳转到对应文件行
* *多格式只读预览*：EPUB、FictionBook 2（`.fb2` / `.fb2.zip` / `.fbz`）、Kindle（`.mobi` / `.azw` / `.azw3` / `.kf8`）、漫画 ZIP（`.cbz`）、PDF、Word、PowerPoint；图片与漫画共用同一阅读器（翻页 + 缩放）。Excel 是唯一仍可编辑的格式
* 关系图谱（全局 / 局部、过滤、分组；断链边虚线标出）、反向链接、出链、大纲、全文搜索、命令面板
* Obsidian 插件与主题兼容层：从库内 `.obsidian/` 加载插件与主题
* 可选的分盘备份：把整个库打成 ZIP 写到另一块盘、网络盘或网盘同步目录；默认关闭

== 还不能用的

[options="header"]
|===
|能力 |状态
|AsciiDoc 结构化编辑 |源码模式已有独立语言模式、语法高亮、xref 点击跳转、章节折叠与大纲导航；下划线式标题，以及示例 / 侧栏 / 引用 / 开放块内部的结构识别仍未适配
|引用校验的深水区 |三态校验面板与图谱断链边已上线；仍缺锚点（标题 / 书签）存在性判定、条件包含求值、按组件筛选扫描范围、发布前全量检查，以及校验结果导出
|Canvas（`.canvas`） |未开始；设置里有开关，门后是空的
|Git 集成 |未开始，不调用任何 git 命令
|自研同步引擎 / 多机并发合并 |明确不做；只提供上面提到的整库 ZIP 备份
|===

*一句话概括*：adoc 现在能进图、能参与反链，阅读视图与源码折叠 / 大纲正常，主要缺口在更深的校验（锚点存在性）与非标准块结构识别。

== 快速开始

环境要求：

* Node.js 22（仓库 `.nvmrc` 固定 `22.23.2`，CI 以该文件为准）
* Rust stable + Cargo（Tauri 2.12 的 MSRV 为 1.90）
* Windows 需 Visual Studio 2022 的 C++ 工具链与 WebView2 运行时；其他平台见 https://tauri.app/start/prerequisites/

从源码构建：

[source,sh]
----
git clone https://github.com/Janlhin/AsciiDoc_Knowledge_Manager.git
cd AsciiDoc_Knowledge_Manager
npm install
npx tauri build --no-bundle     # 只出可执行文件，最快；首次编译约 2 分钟
----

手上有一个示例库，可以直接跑起来看：

[source,sh]
----
src-tauri/target/release/adkm.exe demo-vault
----

第一个参数会被当作 vault 根目录，跳过文件夹选择对话框；省略参数则恢复上次打开的库。Windows 上也可以右键 `run-adkm.ps1` →「使用 PowerShell 运行」。

出 NSIS 安装包（带自动更新签名需要私钥）：

[source,sh]
----
npx tauri build
----

产物位于 `src-tauri/target/release/adkm.exe`（约 9.8 MiB，unsigned 构建实测 10,289,152 字节）与 `src-tauri/target/release/bundle/nsis/`。发版流程与产物校验见 `docs/release-checklist.adoc`。

[quote]
____
*不要只跑 `cargo build --release`。* exe 里嵌入的前端资源由 `tauri build` 链路刷新，只编译 Rust 侧会得到一个能启动、但界面全白的 exe。改完前端代码必须走完整链路。
____

== 开发

[source,sh]
----
npm run dev          # 浏览器里跑前端（vite-plus dev server）
npx tauri dev        # 桌面窗口开发模式
npm run typecheck    # tsc --noEmit
npm test             # vitest
npm run verify       # typecheck + 脚本 typecheck + 命令注册校验 + 单测 + 生产构建
----

样式改动提交前请先 `npm run build`，并确认编译后的 CSS 规则集合没有意外变化。两个文件永远保持 `.css` 不要转 SCSS：`src/compat/obsidian/theme-bridge.css`、`src/features/export/export.css`（它们通过 `?raw` 原文注入）。调色板（`:root` 与 `html[data-theme]`）保持 CSS 自定义属性，Obsidian 主题会在运行时覆盖。

== 参与贡献

* 先开 issue 说明问题或想法，再动代码；未讨论的大改动容易被搁置。
* 直接 fork 仓库提 PR 即可。`main` 受分支保护：需要 PR、至少 1 个批准，禁止强推与删除分支。
* 提交信息用 Conventional Commits（`feat:` / `fix:` / `docs:` / `refactor:` / `test:` / `chore:`），一个提交只做一件事。
* 细节见 xref:docs/CONTRIBUTING.md[`docs/CONTRIBUTING.md`]。
