=== 新增

* **千篇 adoc 性能基准（T-069 / D-044）**：新增可复现脚本 `scripts/adoc-1000-bench.ts`（确定性夹具、冷热分轮、中位数 / p95 与逐轮样本），报告见 `docs/perf-1000-adoc.adoc`。本机实测（9800X3D / 32GB / Node v22.23.2）：索引冷构建聚合中位 130.44 ms、引用校验 416.06 ms、结束时 heapUsed 78.03 MB / RSS 179.41 MB，对照章程 §9.1（30s / 5s / 500MB）三项达标；口径仅限 TS 侧计算路径，未测 Rust FTS5 写入与 WebView/Tauri 占用。
* **`.txt` 入索引（T-068 / D-043）**：纯文本 `.txt` 与 `.md` / `.adoc` 同索引——正文可全文搜索、走既有文本编辑 / 阅读视图，`xref:foo.txt[]` / `link:foo.txt[]` 可按路径解析。txt 按**无结构**处理：不提取标题 / 章节 / 链接 / 标签，不猜首行标题、不伪造层级；超大正文仍按索引字符上限截断。零新增依赖，12 条新单测覆盖正反向用例（含大小写扩展名、路径含空格、二进制 / 未知扩展名排除）。

* **GPU 图谱原型（Q-011 / D-037）**：新增 `scripts/graph-scale-webgl-layout.html`。WebGL2 浮点纹理 ping-pong 做近似 GPU 力导，点/边直接从状态纹理渲染；10 万节点/20 万边在 RTX 5080 + Edge 上 **164.1fps、6.09ms/帧**，GPU 平均 14%、峰值 49%。这是原型，不是生产 `GraphView` 替换；无标签、拾取、拖拽、过滤与数据接线。

* **Q-011 图谱规模 spike（D-036）**：新增 `scripts/graph-scale-bench.ts` 与 `scripts/graph-scale-webgl.html`，用可重复合成图分离布局与绘制成本。实测 10 万节点 WebGL 绘制约 0.6ms，但 d3-force 单 tick 约 925ms、15 秒仅 17 tick；当前 419 节点图谱绘制 0.4ms。结论是 WebGL 不是当前瓶颈，生产 `GraphView` 未改。

* **备份分块写入，修复大库静默 0 字节归档（D-035）**：备份 ZIP 不再作为单个 base64 IPC 参数传输（440MB 库实测会静默写出 0 字节），改为 4MB 分块 append 到 Rust 临时文件后原子 rename。同一 440MB 夹具生成 461,536,071 字节归档，可正常读出 40 个条目。E2E 夹具清空逻辑同时修正，避免 40MB 副本累积污染备份用例。

* **重内容默认点击加载（Q-007 / D-034）**：启动恢复时，PDF/EPUB/Office/CBZ 默认只恢复标签并显示“加载内容”，未点击前不读取文件；设置 → 启动行为新增二态开关，可改为自动加载（含 32MB+ PDF）。真实库 22 本（757MB）验证：默认为按需时 22/22 在 3–11ms 进入占位；切自动后 22/22 成功挂载，最慢 697ms；22 个标签重启时只挂载当前标签。

* **DOCX/XLSX 解析移入 Worker（T-062 / D-033，P1-1 + P1-2）**：mammoth 的 OOXML→HTML 转换与 SheetJS 的工作簿解析分别由专用 Worker 执行，主线程保留 DOCX 的 HTML 渲染、XLSX 的网格与显式 Save；Worker 失败自动回退页内解析。E2E 新增 `docx-worker-offthread`、`xlsx-worker-offthread`：同一构建中分别跑 Worker/页内两条路径，断言 Worker 真在使用且 HTML/数据等价；`--only=<case>` 可单独跑某条用例。真机数据：DOCX 46/9 ms、XLSX 25/18 ms（Worker/页内）——**这是 CPU 卸载，不是提速声明**。全套 E2E 24/24。

* **AsciiDoc 转换移入 Web Worker（T-062 / D-032，P1-3）**：`@asciidoctor/core` 的 `convert()` 现在由独立 Worker 执行，主线程只保留 HTML 清理与站内链接改写；Worker 失败自动回退页内转换，预览不会中断。E2E 新增 `adoc-worker-offthread`：同一构建中分别跑两条路径，断言 Worker 被实际使用且产出 HTML 与页内一致。**实测：1000 节文档 Worker 47ms / 页内 38ms，主线程定时器延迟约 1ms / 0ms——本项是 CPU 卸载，不是可测的提速**。全套 E2E 22/22。

* **原始字节 IPC（T-062 / D-031，P0-1）**：桌面端文件读取不再走 base64 字符串 + 前端逐字节解码——144 MB 文件此前仅解码就占主线程约 322 ms。现在 Rust `vault_read_binary` 返回 `tauri::ipc::Response`（`ArrayBuffer`），`vault_write_binary` / `vault_modify_binary` 接收原始 body，路径由 UTF-8 base64 header 传递；上层 `readBinary` / `createBinary` / `modifyBinary` 签名不变。新增 E2E `raw-binary-ipc`：40 MB 文件读→写→读字节完全一致，主线程帧间隔 0 ms。全量 E2E 21/21。**这不是全场景多核的完成态**：解压、解析、备份压缩与图谱布局仍待后续阶段。

* **EPUB 阅读器补全：目录、翻页、阅读位置（T-061 / D-030）**：原来的 EPUB 预览只有 83 行、只调 `display()`——**没有目录、没有进度**，每本书永远从第一页打开，跳转一关就丢（EPUB 此前在 E2E 里零覆盖，所以没人发现）。现在有工具栏（目录 / 上一页 / 百分比 / 下一页）、按层级缩进的目录侧栏、当前章高亮、方向键翻页；阅读位置按 `{cfi, index, percent}` 去抖保存，重启后回到原处，CFI 失效时回退第一页。百分比用 spine 索引计算（O(1)），刻意不用 `locations.generate()`——那会为了进度条把 50MB 的书在主线程数秒。
* **大 PDF 不再拖慢启动（T-060 / D-029）**：用户确认启动卡顿来自 PDF 标签，实测证实——恢复一个 60 MB PDF 会在首绘后造成 **72 ms + 151 ms** 两次主线程阻塞（EPUB 与普通笔记标签均无此问题）。现在 PDF 一律**延后两帧**（跨过启动首绘）才开始读文件；**超过 32 MB 的不再自动读取**，改为显示大小与「加载 PDF」按钮，点击后才加载（与浏览器对大插件内容的策略一致）。同一会话复测：启动窗口内零卡顿。新增夹具（结构合法的小 PDF + 40 MB 桩文件）与 E2E 第 16 条 `pdf-startup-gate`。
* **启动首帧主题引导（T-059 / D-028）**：修复启动瞬间的颜色闪变。先取证后改：CDP `PerformanceObserver` 测得 800 条笔记的库 FCP **176 ms**、无 >50 ms 长任务，说明不是计算量问题；真正原因是 `:root` 默认深色而 `data-theme` 要等 bundle 才写，浅色主题用户每次启动先看到一帧深色。现由 `index.html` 的内联脚本在 bundle 之前读取主题镜像键（`adkm.theme`，由 `setTheme` / `applyDocumentEffects` 同步）并写入 `data-theme`，配两行关键 CSS 保证首帧底色；存储被禁时自动退化为旧行为。E2E 断言「引导时间戳 ≤ bundle 开始时间」与「计算背景色与主题一致」。
* **启动行为可选（T-058 / D-027）**：设置新增「启动」分区，可选**继续上次打开的标签**（默认，即既有行为）或**全新窗口打开**。`fresh` 模式启动时不重放面板树与标签，**但也不覆盖已保存的会话**——切回 `restore` 仍能恢复上一次的标签；代价是 fresh 会话中的标签变化不被记忆，已写入设置文案。判断集中在 `core/startup.ts` 的两道闸门，`Workspace` 的 `restore` / `persist` / 切库采用各问一次。4 条单测 + 真机 E2E 20/20（新增 `startup-mode`：改设置 → 重载 → 0 标签；切回后重载 → 标签回来）。
* **可选分盘 / 异地备份（T-057 / D-026，Q-006 结案）**：命令「选择备份文件夹…」+「立即备份整个库」。把原稿与 `.obsidian` 配置树（书签、工作区、编辑快照）打成带时间戳的 ZIP，写到**用户亲手选的目录**——可以是另一块盘、网络共享，或网盘客户端已同步的文件夹（这就是最短的"上云"路径，不引入账号/协议/自研同步）。目标不得在库内（防自我递归）；保留份数默认 10（上限 100），旧包按名字顺序清理；**删除动作只对 `adkm-backup-*.zip` 生效，并在 Rust 侧二次校验**，不可能被前端 bug 或插件利用成通用删除。`.trash` 与点目录不入包。新增 15 条单测 + 真机 E2E 14/14（`offdisk-backup`：真实写出 ZIP、校验内容、拒绝库内目标、`keep=1` 只剩一份）。**章程 `:958`「不做云端服务」由 D-026 局部修订**，自研同步引擎仍不做（T-048 有效）。使用说明见 `docs/backup-guide.adoc`。
* **文件恢复覆盖全部文本格式（T-056 / D-025）**：编辑快照（文件恢复）原只认 `.md`，AsciiDoc 这个双一等公民反而没有历史。现改为「编辑器能当文本打开的全部格式」——`.adoc` / `.asciidoc`、`.txt` / `.log` / `.rst`、源码与配置；判定复用 `isEditableTextPath()`（与附件路由同一真源），二进制与未知扩展名永不快照。自动捕获加 **512 KB 上限**（超限按路径记忆、只告警一次），**强制捕获（还原前备份当前内容）不受限**，避免「没备份就覆盖」。16 条新单测 + 真机 E2E 13/13（新增 `snapshot-text-formats`：保存 `.adoc` 后快照数增加、图片始终 0）。同时明确冗余边界：应用内只做「撤销级」恢复，跨盘冗余交给系统（Q-006 待选路线）。
* **Kindle 家族只读预览（T-055 / D-024，Q-005 结案）**：新增 `.mobi` / `.azw` / `.prc` 与 `.azw3` / `.kf8` 只读预览，章节按需加载，不可信章节 HTML 一律降为 React 文本块（标题/段落/图片），`<script>`/`<style>`/注释子树整棵剥离，绝不 `innerHTML`；切文件或卸载时调用解析器 `destroy()` 释放 blob URL。这是本项目**首次引入新的运行期依赖**：仅 `@lingo-reader/mobi-parser@0.4.6`（MIT、196 KB、浏览器独立入口、`--save-exact` 钉选），逐项登记见 `MANIFEST.md`。Q-005 第二问按 D-022 维持编辑能力冻结（保留 Excel 显式保存）。CBR/CB7、HEIC/HEIF、DJVU/TIFF/JXL 仍不引入。11 条新单测 + 2 处负向自检，真机 E2E 12/12（新增 `kindle-formats`）。详见 `docs/format-preview-baseline.adoc`。

== 2.0.0 — 2026-11-12

本版本为重写立项书，反映交付形态与技术实现基础的重大变更。不构成对 1.x 内容的增量修订，而是一次方向调整。

=== 不兼容变更

* **交付形态**：VS Code 扩展（首期）+ 桌面应用（长期）→ **桌面应用即为首期**。原 §6「VS Code 插件设计」整章删除。
* **实现策略**：从零构建核心引擎 → **以 ADKM 为底座 fork 后增量扩展**。
* **技术栈**：TypeScript + 待定桌面壳 → **Tauri 2 + React 19 + TypeScript 7 + CodeMirror 6 + vite-plus**。
* **格式定位**：AsciiDoc 为核心、MD/TXT 附带 → **Markdown 与 AsciiDoc 双一等公民**。
* **产品价值**：双向链接与关系图谱 → **跨格式引用完整性校验优先**。
