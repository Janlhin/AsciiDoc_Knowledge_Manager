== 未发布（Unreleased）

=== 新增

* **启动行为可选（T-058 / D-027）**：设置新增「启动」分区，可选**继续上次打开的标签**（默认，即既有行为）或**全新窗口打开**。`fresh` 模式启动时不重放面板树与标签，**但也不覆盖已保存的会话**——切回 `restore` 仍能恢复上一次的标签；代价是 fresh 会话中的标签变化不被记忆，已写入设置文案。判断集中在 `core/startup.ts` 的两道闸门，`Workspace` 的 `restore` / `persist` / 切库采用各问一次。4 条单测 + 真机 E2E 15/15（新增 `startup-mode`：改设置 → 重载 → 0 标签；切回后重载 → 标签回来）。
* **可选分盘 / 异地备份（T-057 / D-026，Q-006 结案）**：命令「选择备份文件夹…」+「立即备份整个库」。把原稿与 `.obsidian` 配置树（书签、工作区、编辑快照）打成带时间戳的 ZIP，写到**用户亲手选的目录**——可以是另一块盘、网络共享，或网盘客户端已同步的文件夹（这就是最短的"上云"路径，不引入账号/协议/自研同步）。目标不得在库内（防自我递归）；保留份数默认 10（上限 100），旧包按名字顺序清理；**删除动作只对 `adkm-backup-*.zip` 生效，并在 Rust 侧二次校验**，不可能被前端 bug 或插件利用成通用删除。`.trash` 与点目录不入包。新增 15 条单测 + 真机 E2E 14/14（`offdisk-backup`：真实写出 ZIP、校验内容、拒绝库内目标、`keep=1` 只剩一份）。**章程 `:958`「不做云端服务」由 D-026 局部修订**，自研同步引擎仍不做（T-048 有效）。使用说明见 `docs/backup-guide.adoc`。
* **文件恢复覆盖全部文本格式（T-056 / D-025）**：编辑快照（文件恢复）原只认 `.md`，AsciiDoc 这个双一等公民反而没有历史。现改为「编辑器能当文本打开的全部格式」——`.adoc` / `.asciidoc`、`.txt` / `.log` / `.rst`、源码与配置；判定复用 `isEditableTextPath()`（与附件路由同一真源），二进制与未知扩展名永不快照。自动捕获加 **512 KB 上限**（超限按路径记忆、只告警一次），**强制捕获（还原前备份当前内容）不受限**，避免「没备份就覆盖」。16 条新单测 + 真机 E2E 13/13（新增 `snapshot-text-formats`：保存 `.adoc` 后快照数增加、图片始终 0）。同时明确冗余边界：应用内只做「撤销级」恢复，跨盘冗余交给系统（Q-006 待选路线）。
* **Kindle 家族只读预览（T-055 / D-024，Q-005 结案）**：新增 `.mobi` / `.azw` / `.prc` 与 `.azw3` / `.kf8` 只读预览，章节按需加载，不可信章节 HTML 一律降为 React 文本块（标题/段落/图片），`<script>`/`<style>`/注释子树整棵剥离，绝不 `innerHTML`；切文件或卸载时调用解析器 `destroy()` 释放 blob URL。这是本项目**首次引入新的运行期依赖**：仅 `@lingo-reader/mobi-parser@0.4.6`（MIT、196 KB、浏览器独立入口、`--save-exact` 钉选），逐项登记见 `MANIFEST.md`。Q-005 第二问按 D-022 维持编辑能力冻结（保留 Excel 显式保存）。CBR/CB7、HEIC/HEIF、DJVU/TIFF/JXL 仍不引入。11 条新单测 + 2 处负向自检，真机 E2E 12/12（新增 `kindle-formats`）。详见 `docs/format-preview-baseline.adoc`。
* **文档规范体检（T-046）**：命令「检查文档规范」+ 主区单例结果面板「文档体检」。六项规则（术语一致性、失效链接、标题跳级、必填元数据缺失、章节结构、中文标点），按严重度/类别聚合，点问题行跳转。纯函数规则引擎，零新增依赖；规则上下文 `AUDIT_RULE_DOCS` 供 T-047 的 AI 校对复用。详见 `docs/doc-audit-baseline.adoc`。
* **AI 按规范校对（T-047）**：命令「按规范校对当前笔记」+ AI 面板勾选按钮。把当前笔记、六条规则、术语词表与确定性体检结果组成提示词，要求模型返回单个 `json` 围栏；回复解析成**可跳转的问题列表**，行号越界/缺字段的条目丢弃并计数，无法解析时保留原文并明确提示。复用 AI 面板唯一一条流式路径，零新增依赖；E2E 用本地 mock LLM 覆盖全链路。详见 `docs/ai-proofread-baseline.adoc`。
* **Docs-as-Code 引用校验（T-045 首片）**：文档体检新增 `broken-xref` / `broken-include` 两类——AsciiDoc `xref` 按「文件相对 → 库根相对」解析（显式 `./` 不回退），`include::` 按文件相对解析并检测全库环（A→B→A 只报一次）；Antora 资源 ID 无唯一同名文件时按「无法判定」warning 处理，不臆断。顺带修正 `.adoc` 元数据兜底误用 Markdown 解析器的缺陷。零新增依赖。详见 `docs/docs-as-code-baseline.adoc`。
* **Antora 组件/版本资源 ID（T-045 第二片）**：体检运行器读取库内全部 `antora.yml`（复用既有 `js-yaml`，零新增依赖），按 `modules/<module>/<family>/` 建立组件版本索引；`[version@]component[:module][:family$]path` 形式的 xref / include 改为按组件与版本精确解析。省略版本时只采用**当前文件所属的版本**，多版本且无法判定时报「匹配到 N 个组件版本，无法确定」warning，不猜版本；无描述符的库保持首片行为。19 条新单测 + 2 处负向自检，真机 E2E 9/9（新增 `antora-components`）。详见 `docs/docs-as-code-baseline.adoc`。
* **只读电子书格式扩展与图片阅读器（T-054 / D-022）**：新增 FictionBook 2（`.fb2` / `.fb2.zip` / `.fbz`）与漫画 ZIP（`.cbz`）只读预览；单张图片与漫画页共用 `ImageReader`（数值排序翻页 + 缩放），FB2 以 React 文本节点渲染避免注入。所有新组件经 `useFormatResource` 统一「可取消加载 + 资源释放」，并已合并 PR #27 的 EPUB 生命周期修复。**零新增运行期依赖**。按用户决定**冻结编辑能力**：仅保留 Excel 的显式保存，撤销 D-013 的 DOCX 真编辑 phase-2。MOBI/AZW3/DJVU/CBR/HEIC 等候选已完成「先搜寻后自研」评估但未引入，见 `MANIFEST.md` 与 Q-005。真机 E2E 10/10。详见 `docs/format-preview-baseline.adoc`。
* **Antora 组件/版本切换（T-045 第三片 / D-023）**：文档体检面板新增「组件版本」选择器。选中某一版本后，**省略版本的资源 ID 按所选版本解析**（不再按当前文件所属版本），显式 `version@…` 仍优先，纯路径目标语义不变；报告附带库内检测到的组件/版本清单。会话级 Store 使命令面板与「重新体检」沿用同一 pin，零新增依赖。10 条新单测 + 2 处负向自检，真机 E2E **11/11**（新增 `antora-version-switch`）。**边界**：pin 只改引用解析，体检仍扫描全库，未做按组件筛选/发布前检查/按组件导出。详见 `docs/docs-as-code-baseline.adoc`。

== 2.0.0 — 2026-11-12

本版本为重写立项书，反映交付形态与技术实现基础的重大变更。不构成对 1.x 内容的增量修订，而是一次方向调整。

=== 不兼容变更

* **交付形态**：VS Code 扩展（首期）+ 桌面应用（长期）→ **桌面应用即为首期**。原 §6「VS Code 插件设计」整章删除。
* **实现策略**：从零构建核心引擎 → **以 Geode 为底座 fork 后增量扩展**。
* **技术栈**：TypeScript + 待定桌面壳 → **Tauri 2 + React 19 + TypeScript 7 + CodeMirror 6 + vite-plus**。
* **格式定位**：AsciiDoc 为核心、MD/TXT 附带 → **Markdown 与 AsciiDoc 双一等公民**。
* **产品价值**：双向链接与关系图谱 → **跨格式引用完整性校验优先**。
* **文档位置**：新立项书位于 `docs/project-charter-v2.adoc`；1.x 版保留于项目根目录作为历史。

=== 技术栈版本升级（2026-11-13 补记）

底座 geode（快照 `7a8ce22`，2026-07-04）当时的版本为 **React 18.3.1 / TypeScript 5.7.0 / Tauri 2.2.0 / Vite 6 / 未引入 sass**。本项目随后升级为：

[cols="1,1,1"]
|===
|层 |底座 |现在

|React |18.3.1 |19.3.1

|TypeScript |5.7.0 |7.0.2

|Tauri |2.2.0 |2.12.5

|构建 |Vite 6 |vite-plus 1.6.0（含 Vite 8 + Rolldown）

|样式 |原生 CSS |SCSS（sass 1.108.2），`src/` 内 0 个 `.css`

|依赖条目 |46 |60
|===

因此上一节「不兼容变更」中的技术栈一行记的是**当前状态**而非立项时的原始选择。逐项对照见 `docs/geode-baseline.adoc`。

=== 新增

* ADR-0003：交付形态与实现基础的选择。
* ADR-0004：策略由最小增量改为深度改造，含七层结构与样式三规则。
* `docs/route-evaluation.adoc`：九款开源笔记软件的实测核查与五条路线对照。
* `docs/obsidian-clone-report.adoc`：六个 Obsidian 模仿品的代码级核查与三维度排名。
* `docs/obsidian-reverse-engineering.adoc`：以 REA 逆向 Obsidian 本体的学习路线规划，含分析目标核实（`resources/主程序资源包`，非 73 KB 启动壳）、九条优先学习项（软件逻辑五条 + 代码逻辑四条）、三阶段方法与「不可映射不进 ADR」的输出纪律。
* `docs/geode-baseline.adoc`：ADKM 相对底座 geode 的差异基线。确立「评估差距时参照物必须是底座 geode，而非参照产品 Obsidian」，含核实自 package.json / Cargo.toml 的完整技术栈版本表（底座当时 vs 现在两栏）、版本号来源辨析（`tauri.conf.json`、`package.json`、`Cargo.toml` 现均为 0.269.0），`git diff 6e80e93 HEAD` 实测的量化差异（110 文件 / +13476 −4408；`src/` TS 净增 1231 行即 +2.4%，扣除 CSS→SCSS 机械改写与文档后），并明确「架构成熟度」是唯一大缺口且底座同样缺失。
* §4「格式支持与解析分层」，含 L1–L4 能力分级与 AsciiDoc 的 D1–D4 解析边界。
* §4.4 解析上下文（衔接 ADR-0002）。
* §4.5 跨格式引用统一模型（`LinkRef` 与归一规则）。
* §5.1 引用校验：有效 / 断链 / 未解析三态报告。
* §5.2 多版本一致性校验：版本号、章节数量、章节结构、行数偏差。
* §5.4 关系类型扩展：`related-to` 来自 Obsidian Canvas。
* §12.2 上游义务：Apache-2.0 的 NOTICE 与版权声明要求。
* §13 风险表新增「上游合并成本」「产品定位模糊」两项。

=== 保留

* 核心原则（本地优先、数据独立、可重建、上限可信）。
* AsciiDoc 解析不得以正则代替完整解析器的原则（细化为 D1–D4）。
* ADR-0001、ADR-0002 全部继续有效。
* 治理条款与 AI Agent 约束。

=== 说明

* 明确不做：AsciiDoc 实时内联预览（L4）、AsciiDoc 转 Markdown、PDF/EPUB 输出、自动版本备份（属独立项目）。
* Obsidian 插件兼容层保留，仅对 Markdown 文件生效。

== 0.1.1 — 2026-11-12

本版本为立项阶段的技术验证修订，不改变项目目标与范围，仅将章程中的技术假设替换为经实测确认的结论。

=== 新增

* ADR-0001：Asciidoctor.js 4.x 能力边界与解析分层策略。
* ADR-0002：解析上下文模型（include 归属、属性优先级与条件求值）。
* 章程 §4.4.1：解析上下文。
* 章程 §16.3：ADR 文件命名约定与已收录索引。

=== 变更

* §4.2：「解析器优先采用 Asciidoctor.js」改为「解析器采用 Asciidoctor.js 4.x」。
* §4.2：「禁止直接使用不受控的正则表达式代替完整 AsciiDoc 解析器」改为可执行的分层边界（块级由解析器提供、行内受控解析、误判降级）。
* §5.2：技术选型表补充 4.x 的 ESM 与异步约束；表格后新增「接口性质」小节。
* §9.1：明确增量索引的粒度为文件级，并注明解析器不提供内部增量能力。
* 文档头：`:revnumber` 由 0.1.0 升至 0.1.1，新增 `:revremark`。

=== 修正

* §11.2：增补 5 项测试场景，覆盖上下文一致性、include 归属、属性缺失降级、条件块差异、循环引用检出。
* §14：增补「解析上下文不确定」风险项。
* §15：增补「相同解析上下文下重复索引结果一致」验收条件。
* 文末声明：原文称「不代表所有技术选型已经经过实测」，与 ADR-0001 记录的实测结论矛盾，已修正表述。
