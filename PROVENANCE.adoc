== 与上游的关系

本仓库采用**内嵌基线**形态，不是活跃 fork：

. 首个提交为基线提交的完整快照，git 历史自该点起独立。
. 上游仓库保留为只读远端，仅用于按需摘取单个提交，不进行合并或变基。
. 不跟随上游的常规提交，不承担上游重构的适配成本。

== 保留的上游能力

=== Obsidian 插件兼容层

`src/compat/` 全部保留，共约 10,397 行。

**保留理由**：该层使本产品能够加载 Obsidian 社区插件与主题，是差异化能力的一部分，不属于待清理的历史包袱。它仅对 Markdown 文件生效；AsciiDoc 文件不经过该层。

=== 样式机制的两个不可动点

以下约束在后续改造中必须持续遵守，原因与许可无关，与技术正确性有关：

. `theme-bridge.css` 与 `export.css` 保持为 CSS，不转 SCSS。
. `:root` 与 `html[data-theme]` 中的调色板字面量保持为 CSS 自定义属性，不转为编译期变量。原因有二：Obsidian 主题在运行时覆盖这些变量；`theme-bridge.css` 头部要求调色板与其逐字同步，变量化后无法用文本检索校验。

=== 关于导入路径修改的说明

23 个 TS/TSX 文件的修改仅为样式导入路径的一行变更。此类修改未在文件内逐处加注，理由是其完整清单可由基线提交与本仓库首次提交之间的差异精确复现：

[source,bash]
----
git diff base-geode-7a8ce22 -- "*.ts" "*.tsx"
----

对该命令的输出逐条审阅，即可完整核对本项修改范围。
