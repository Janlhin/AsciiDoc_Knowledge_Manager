= 备份指南（T-057 / D-026）
:日期: 2026-11-16

== 一句话

应用提供两条命令：**选择备份文件夹**、**立即备份整个库**。它把你的库打成一个带时间戳的 ZIP，放到**你亲手选的那个目录**里。那个目录可以是另一块盘、NAS 共享，也可以是 OneDrive / 坚果云这类客户端已经同步的文件夹——后者就是最短的"上云"路径，不需要账号、协议或自研同步。

== 三步上手

. 命令面板（`Ctrl+P`）→「选择备份文件夹…」→ 选中目标（例如 `D:\ADKM-backup` 或 `C:\Users\你\OneDrive\ADKM`）
. 命令面板 →「立即备份整个库」
. 去那个文件夹确认出现 `adkm-backup-20261116-121930.zip`；底部通知会报文件名与文件数

目标一旦记住，下次只需第 2 步。**应用不会自己往任何你没选过的位置写东西**。

== 包里有什么

[cols="2,1,3",options="header"]
|===
| 内容 | 入包 | 原因

| 原稿（`.md` / `.adoc` / `.txt` / 源码与配置）
| 是
| 唯一不可重建的东西

| 附件（图片、PDF、Office、电子书、音频视频）
| 是
| 用户资产，丢了就得重新找

| `.obsidian/` 配置树（书签、工作区、编辑快照、插件列表与设置）
| 是
| 你自己攒的数据；编辑快照还带 25 份历史

| `.trash/`
| **否**
| 删除恢复的辅助区，体积大，不属于灾难恢复必需

| `.git/` 与其他点目录
| **否**
| 机器状态或缓存，跨机器无意义

| 索引库、搜索库、缓存
| **否**
| 章程「数据可重建」：它们能从原稿重新算出来
|===

== 保留多少份

默认保留 **10 份**，上限 100。旧包按文件名排序（名字里带 `YYYYMMDD-HHmmss`，所以名字序＝时间序）从旧到新清理。

删除动作有两道约束：**只对本应用命名的 `adkm-backup-*.zip` 生效**，且这个判断在 Rust 侧再校验一次。即使前端出 bug 或被恶意插件调用，也不可能变成"删除任意文件"。

== 三层防线怎么搭

[cols="1,2,2",options="header"]
|===
| 层 | 它防什么 | 谁负责

| 撤销键（`.trash` + 编辑快照）
| 手滑删除、改坏了想翻旧稿
| 应用自动，库内，**同盘**

| 分盘备份（本功能）
| 库文件夹被整体删除、换机器、误格式化
| 你点两下；文件到另一块盘或网盘

| 系统备份（文件历史记录 / 卷影副本 / 存储空间镜像）
| 磁盘物理损坏、整台机器丢失
| 你在 Windows 里配一次
|===

[IMPORTANT]
====
**镜像 ≠ 备份。** 存储空间镜像（RAID1）是"同时写两份"，你误删、中勒索病毒加密时两份会一起没；它只防硬盘坏。真正能救"改坏/删错"的是**带时间点的历史**：编辑快照、本功能的 ZIP、文件历史记录。
====

== 三个坑

. **OneDrive 占位文件**：库如果放在「桌面/文档」且开了 OneDrive 文件夹备份，本地可能只有占位文件。此时读取会触发下载，甚至拿到占位内容。建议库放非 OneDrive 目录（如 `D:\vault`），或对该文件夹选"始终保留在此设备上"。
. **不要两端同时写同一个库**：备份目录放网盘没问题（我们只往里写新文件）；但**正在使用的库本身**不要同时被两台机器或两个客户端写，那会产生互相覆盖，本功能不解决合并。
. **包是明文的**：ZIP 不加密。放到共享网盘前，请考虑放进加密卷/容器。

== 不做的事（诚实边界）

* **不定时**：当前只有手动命令；定时需要设置界面，属下一片。
* **不增量**：每次都打全量 ZIP，大库会有可感知的 IO 成本。
* **不解决多机并发**：没有 base 快照、没有 diff3 合并，这是同步引擎的范畴，T-048 明确不做。
* **不内置账号/服务端**：想"上云"就把目标指向网盘客户端已同步的目录。
