== 这份文档管什么

为 GPU 图谱（T-063）建立可复跑的布局与帧时间基准：统一统计口径、
Worker / 档位矩阵、内存与线程记录方式、30 分钟 soak 与 CI 性能回归门禁。
所有数字必须来自脚本真实运行；**改前改后同夹具复测，无数据不得宣称提升**。

本线只动 `scripts/`、`tests/e2e/`、`.github/workflows/` 与仓外证据 JSON；
`src/` 由并行线改动，本线不改生产代码。

关联文档：link:gpu-graph-view.adoc[GPU 视图]。

== 接口约定（脚本照此写，不自创）

- `window.__adkmGpuBench`：`load(nodes, edges, seed?)`、`run(frames?)`
  （返回 `{nodes, edges, frames, samples, medianMs, p95Ms, p99Ms, onePercentLowMs,
  fps, gpu, dpr, width, height, mode}`）、`stop()`；页面需带 `?gpu-bench=1`。
- URL 参数（仅 `gpu-bench=1` 时生效）：`benchWorkerCount`（数字）、
  `benchTier`（S/A/B/C）、`benchSab=off`。
- 布局句柄由池化实现持有，**不挂到 window**；基准脚本在页面内
  `import('/src/features/graph/gpu/layout-client.ts')` 直接 `createAsyncLayout(...)`
  采集 `stats()` 与 `stageMs`，渲染帧仍走钩子。`stats()` 字段：
  `workers/cores/tier/tierReason/sab/wasm/frozen/tickMedianMs/tickP95Ms/tickCount/
  queueDepth/droppedTicks/shardCount/workerBytes`，可选 `stageMs`
  （`buildGridMs/buildQuadtreeMs/repulsionMs/springsMs/integrateMs/mergeMs/summaryMs/totalMs`）。
- 契约暂无 tick p99 字段；`engineTickP99Ms` 记 `null`，不从帧时间或 p95 倒推。

== 统计口径（先读这一节，避免把数字读大）

=== 样本分两类，绝不混算

- **渲染帧样本**：rAF 帧间隔（ms），只包含一帧绘制路径；布局 tick 时间
  **不计入**帧时间。
- **布局 tick 样本**：布局内核单次 `step()` 的耗时（ms）。浏览器侧通过
  `handle.stats()` 的前后差值取 tickCount / tickMedian / tickP95；Node 内核
  基准直接计时单次 `step()`。

=== 分位数定义

样本先升序排序，nearest-rank 取位（与页面内 `quantile()` 一致）：

- 下标 `idx = clamp(round((n - 1) * q), 0, n - 1)`
- median = q0.5，p95 = q0.95，p99 = q0.99。

=== 1% low 算法

- 取最慢的 `k = max(1, ceil(n / 100))` 个帧样本；
- `low1Ms` = 这 k 个样本的算术平均；`low1Fps = round(1000 / low1Ms)`。
- 不使用「把 p99 帧时间倒推成 low fps」的替代写法；p99 单独留在 `p99Ms` 字段。
- 示例：600 帧时 k = 6。

=== 采样与预热

- 每档默认 `run(600)` 帧；`--frames` 可调。
- `load()` 后默认预热 4000 ms（`--warmup-ms`）再采样，避开冷启动编译与
  首次纹理上传。
- 夹具确定性：xorshift32 + 固定 `--seed`，同 seed 同节点数复现同一图。

== 字段字典

=== `layout-<workers>w-<nodes>n-sab<on|off>.json`（基线为 `baseline-` 前缀）

顶层：`schema`、`timestamp`、`repo.git`（commit / subject / dirty）、`env`、
`config`、`render`、`layout`、`memory`、`runError`、`crossCheck`。

`env`：`machine`（cpuModel / logicalCores / platform / arch / osRelease / node /
totalMemBytes）、`edgeVersion`、`browserVersion`、`rendererProbe`（renderer /
unmaskedRenderer / glVersion / ctxType）、`dpr`、`viewport`、`softwareRenderer`、
`diag`（visibility / focus / rafGaps）、`profileDir`。

`render`：

|字段|含义|
|---|---|
|`hook.medianMs / p95Ms / fps / mode / gpu / dpr / width / height`|页面钩子原始返回|
|`samples.count`|实际帧样本数|
|`samples.medianMs / p95Ms / p99Ms`|帧时间分位数（ms）|
|`samples.low1Ms / low1Fps`|1% low 帧时间（ms）与对应 fps|
|`samples.meanMs / minMs / maxMs / fpsFromMedian`|辅助统计|

`layout`：

|字段|含义|
|---|---|
|`handleAvailable`|引擎 stats 采集是否成功|
|`reason`|采集失败原因|
|`requested`|页面请求的 workerCount / tier / sab|
|`observed`|`stats()` 实测 workers / cores / tier / tierReason / sab / wasm / frozen / tickCount / queueDepth / droppedTicks / shardCount / workerBytes|
|`workersMatch`|实测 `observed.workers` 是否等于请求 Worker 数；不等标 `false`，不抹平|
|`mode`|`main` / `pool` 运行模式|
|`tick.deltas`|onTick 墙钟间隔窗口的四件套（median/p95/p99/1% low 等）|
|`tick.engineTickMedianMs / engineTickP95Ms`|引擎滚动窗口内 tick 分位|
|`tick.engineTickP99Ms`|契约暂无，记 `null`|
|`tick.stageMs`|分段耗时（repulsion/springs/integrate/merge/summary/total 等）|

> 两种 tick 口径不要混：`deltas` 是两次 onTick 之间的墙钟间隔（含背压/空闲），
> `engineTick*` 是引擎内核 step 的滚动分位；报告里分列。

`memory`：

|字段|来源|缺失时|
|---|---|---|
|`pageHeap.usedJSHeapSize / totalJSHeapSize / jsHeapSizeLimit`|页面 `performance.memory`（V8 主线程堆）|`null`|
|`cdpProcess.processes[]`|CDP `SystemInfo.getProcessInfo`（pid / type / cpuTime / memory）|`available:false` + reason|
|`cdpMetrics.metrics`|CDP `Performance.getMetrics`（HeapUsedSize 等）|`available:false` + reason|
|`os.rssBytes / os.threads`|本机 WMI：本运行 Edge 树 WorkingSet64 之和 / 线程数之和|`null` + reason|

`fixture`（nodes / edges / seed / ticks / rng）、`positions`（fingerprint /

median / min / max）、`crossings`（approxCount / comparedPairs / cells /

=== `quality-browser-n<nodes>-w<workers>.json`（浏览器侧快照）

`fixture`（nodes / edges / seed / workers / sab / rng）、`observed`（workers /

`quality[]`、`notes`、`errors`。

=== `soak-<nodes>-<minutes>min-<stamp>.json`

`config`、`samples[]`（tSec / heapUsedBytes / totalJSHeapBytes / rssBytes /

samples）、`verdicts`、`overall`、`tickProgress`、`bands`。

== 矩阵计划

=== Worker 档位（模拟，如实标注）

本机 AMD 9800X3D：**8 物理核 / 16 逻辑线程**。`benchWorkerCount` 只改页面
请求的 Worker 数量，**不能关闭 SMT、不能裁物理核**；在本机做的降核对比是
**模拟**结果，不等同于真实少核机器的表现，报告里必须标注「模拟」。

|档|benchWorkerCount|用途|状态（2026-11-28 集成树）|
|---|---|---|---|
|W1|1|单 Worker 基线|已跑（on/off）|
|W2|2|模拟两 Worker|已跑（on/off）|
|W4|4|模拟四 Worker|已跑（on/off）|
|W8|8|模拟八 Worker（16 逻辑核上限内）|已跑（on/off）|

=== 节点 / 开关档

- 节点：100k、200k（synthetic，seed 固定，边数默认 2×节点）。
- SAB：`on` / `off`（`benchSab=off`）。
- WASM：观察项，`stats().wasm` 如实记录，不预设开关。
- 每格记录核数 / Worker 数 / SAB / WASM / heapUsed / RSS / 线程数。

=== SMT 说明

超线程下两个逻辑线程共享执行单元；Worker 数超过物理核后，吞吐不再线性
上涨是预期现象。跨机器比较时必须同时记录 `machine.logicalCores` 与 CPU 型号，
不能只比 fps。

== 内存与线程采集口径

- **V8 堆**：页面 `performance.memory.usedJSHeapSize`，只反映主线程堆；
  Worker 堆不在其中。
- **CDP 进程信息**：`SystemInfo.getProcessInfo` 给 pid / type / cpuTime，
  部分版本带 `memory`；`Performance.getMetrics` 给 HeapUsedSize 等指标。
  两个通道先探可用性，结果写进 JSON 的 `available` 字段。
- **RSS 与线程数**：Windows WMI 枚举命令行带本运行唯一 profile 目录的
  `msedge.exe`，汇总 WorkingSet64 与 `Threads.Count`；非 Windows 标记不可用。
- **每 Worker 峰值**：句柄 `stats()` 暴露了就记；没暴露记 `unknown`，
  **不许**用主线程堆估算成精确值。

== 布局质量对比

不能只看 tick 时间：同 seed 下比较布局几何质量。

- **边长统计**：每条边欧氏长度的 mean / 总体方差 / stddev / median / 极值；
  方差大说明少数弹簧被拉得很长、核心很密。
- **近似交叉数**：网格扫描近似（不是精确扫线计数）：
  1. 世界边界映射到 K×K 网格（`--cells`，默认 32）；
  2. 边按源端点所在格分桶；
  3. 每条边只与两端点包围盒（外扩一格）内桶里的边比较；
  4. 方向叉积判正规相交，共享端点不计。
  比较对数超过 5000 万上限时 `truncated: true`，该报告不与未截断报告比。
- **指纹**：内核 `fingerprint()` 校验同 seed 同 tick 数位置逐位一致。
- **截图**：Node 内核模式无画布；浏览器截图待句柄暴露后由 CDP 流程补。

== Soak 口径与结论

- 默认 30 分钟，每 30 s 采样一次 heapUsed / RSS / 线程数 / tick 数；
  采样间做一轮 pan 拖拽 + 两次缩放。
- 每条序列做最小二乘线性回归，斜率换算为「每分钟」，附 R²。
- 临时增长带宽（provisional，待基线数据校准）：heap > 2 MiB/min、
  RSS > 5 MiB/min、线程 > 0.5/min，且 R² ≥ 0.8 判 `growing`；否则 `stable`；
  数据源不可用判 `unknown`（缺数据不等于稳定）。
- 总体结论取三条序列里最差的一档。

== Soak 结论（100k / 8W / on）

- 实际时长 1788.33 s（29.8 min），59 个采样点，每 30 s 一轮 pan + 两次缩放。
- 回归（OLS，斜率/分钟，R²）：heap +0.17 MiB/min（R² 0.08）、
  RSS −0.65 MiB/min（R² 0.011）、线程 −0.9/min（R² 0.19）；
  三条序列 R² 都很低，斜率不构成统计支持，总体 `stable`。
- 起止：heap 79.0 → 51.7 MB，RSS 1179.9 → 777.2 MB，线程 408 → 278
  （初始 GC / 收敛回落，之后走平）；tick 130 → 227 后平台期（布局收敛停步，
