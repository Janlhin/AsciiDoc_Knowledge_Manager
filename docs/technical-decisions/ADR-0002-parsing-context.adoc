== 1. 背景

在 Markdown 体系下，链接目标是静态文本：扫描一遍文件，引用关系即确定。AsciiDoc 不是。

AsciiDoc 的最终文档由三类机制在解析期合成：

. *include 指令*：将其他文件的内容嵌入当前位置。
. *属性替换*：目标路径本身可以由属性构成。
. *条件包含*：内容只在特定属性组合下才存在。

其结果是：*同一份文件，在不同的属性集下，可以产生完全不同的引用关系图*。

章程 §4.4 与 §4.5 要求实现双向链接与关系图谱，但未规定在上述不确定性下「关系」的确切含义。§4.1 核心原则同时要求「可恢复性」与「可验证性」，这意味着关系图必须是可重现的。

若此模型不预先固定，将出现两类典型故障：

* 同一工作区在两次索引后得到不同的图，且无法解释差异来源。
* 被多处 include 的片段，其反链计数随引用次数线性膨胀，图谱失去参考价值。

== 2. 问题

需要在以下四个维度上做出互不冲突的决策，并保证四项决策的组合结果可重现：

[cols="1,3"]
|===
|维度 |待决问题

|Q1 归属
|被 include 的内容所产生的引用，归属于被包含文件还是包含方？

|Q2 属性
|属性从何而来，优先级如何？索引期是否允许临时覆盖？

|Q3 条件
|条件块内的引用是否进入图谱？若进入，如何标注？

|Q4 可重现
|如何保证「相同上下文产生相同结果」，并在上下文变更时精确失效？
|===

== 3. 可选方案

=== 3.1 Q1 归属

[cols="1,3,2"]
|===
|方案 |说明 |主要缺陷

|A1 归属包含方
|main 包含 part，part 内的 xref 记为 main 的出链
|part 被 N 处 include 时，该引用在图谱中出现 N 次；反链计数与真实引用次数脱钩

|A2 归属被包含方
|part 内的 xref 记为 part 的出链；main 与 part 之间另建 includes 边
|单跳查询看不到「main 经由 part 到底引用了谁」

|A3 双重记录
|同时记录两条边，用边类型区分
|同一语义存在两个数据来源，冲突时无法判定权威值；存储与查询复杂度上升
|===

=== 3.2 Q2 属性

[cols="1,3,2"]
|===
|方案 |说明 |主要缺陷

|B1 仅文档头
|只使用文件自身的文档头属性
|无法表达工作区级共享配置，跨文档属性（如统一的产品名、版本号）需逐文件重复

|B2 文档头优先，工作区默认兜底
|优先级：文档头 > 工作区默认 > 内置默认；索引期不允许临时覆盖
|用户无法临时预览「若属性 X 为 Y 会怎样」

|B3 允许索引期覆盖
|在 B2 基础上允许调用方传入临时属性
|同一文件在不同时刻可产生不同图，破坏可重现性
|===

=== 3.3 Q3 条件

[cols="1,3,2"]
|===
|方案 |说明 |主要缺陷

|C1 求并集
|所有分支内的引用都进入图谱
|产生「幽灵边」：图中存在实际渲染时不会出现的引用，且无法区分

|C2 仅求值默认分支
|只解析属性未定义时的分支，其余丢弃
|丢失「在 html5 后端下会引用 A」这类有效信息

|C3 仅求值默认分支，条件引用标记后另存
|主干图只含无条件引用；条件引用带条件表达式与来源块位置另存，可按需叠加显示
|实现复杂度最高，需要索引结构额外字段
|===

== 4. 最终决定

=== 4.1 Q1：采用 A2（归属被包含方）

图谱节点是*磁盘上的文件*，不是渲染后的文档。据此：

* `part.adoc` 内的 `xref:` 计入 `part.adoc` 的出链。
* `main.adoc` 与 `part.adoc` 之间独立建立 `includes` 类型边。
* 「组装后的完整引用」通过两跳查询获得（`main --includes--> part --xref--> target`），由图谱的局部视图展开深度表达，不作为独立数据结构。

该模型称为*文件视图*，为系统唯一的关系数据来源。

=== 4.2 Q2：采用 B2（文档头优先，工作区默认兜底）

属性优先级，由高到低：

. 文档头属性（`:` *name* `:` *value*）。
. 工作区默认属性（`.adkm/config.json` 的 `attributes` 字段）。
. Asciidoctor 内置默认属性。

索引期不接受临时属性覆盖。

属性值本身允许引用其他属性，须递归求值至稳定，并设置递归深度上限以防循环。

=== 4.3 Q3：采用 C3（默认分支 + 条件引用标记）

* 主干图谱只包含*无条件引用*。
* 条件块内的引用单独记录，字段至少包含：条件表达式原文、所在块的行号范围、求值结果。
* 默认视图不显示条件引用，可由用户显式开启为独立图层。
* 条件引用的求值采用「属性未定义」语义作为默认分支判定依据，与 4.2 的属性集保持一致。

=== 4.4 Q4：上下文版本化

定义*解析上下文*为下列要素的规范化集合：

[cols="1,3"]
|===
|要素 |内容

|属性集
|合并后生效的全部属性及其最终值

|include 归属规则
|固定为本 ADR 4.1 所述文件视图，作为常量参与哈希

|条件求值策略
|固定为本 ADR 4.3 所述默认分支策略，作为常量参与哈希

|解析器版本
|Asciidoctor.js 的实际版本号
|===

系统对上述集合计算规范化哈希，称为*上下文指纹*，并执行：

. 每条索引记录附带其上下文指纹。
. 上下文指纹变更时，受影响文档标记为待重索引；指纹未变更的文档不得重解析。
. 查询时若发现记录指纹与当前上下文不一致，须降级为「可能过期」并触发重索引，不得静默返回旧图。

=== 4.5 循环 include 与深度限制

* 必须在解析前检测 include 环（A 包含 B、B 包含 A），检测到环时记录错误并终止该分支，保留其余部分的解析结果。
* 深度超过阈值时记录明确错误，*不得静默截断*。静默截断会使图谱不完整且不可察觉。
* 被拒绝的 include 在结果中标记为 `unresolved-include`，与普通断链（`broken-link`）区分。

== 5. 方案比较小结

[cols="1,1,1,2"]
|===
|维度 |采纳方案 |被否决方案 |否决主因

|Q1
|A2 文件视图
|A1 / A3
|A1 使反链计数失真；A3 引入双权威数据源

|Q2
|B2 文档头优先
|B1 / B3
|B1 无法共享工作区配置；B3 破坏可重现性

|Q3
|C3 默认分支 + 标记
|C1 / C2
|C1 产生幽灵边；C2 丢失有效信息

|Q4
|上下文指纹
|无（新增要求）
|章程 §4.1 的「可验证性」要求结果可重现
|===

== 6. 决定理由

. **可重现性是图谱可信度的前提。** 一个无法解释差异来源的图，用户不会用它做判断。上下文指纹把「为什么两次索引结果不同」从不可知变为可定位。
. **文件视图与实际维护行为一致。** 用户编辑、提交、重命名的最小单位是文件，不是组装后的文档。节点与文件一一对应，避免了「文档节点与文件节点并存」的模型分裂。
. **条件引用不应被丢弃，也不应污染主干。** 分开存储同时满足了两点，代价是一个额外字段和一次图层切换，成本可控。
. **属性覆盖属于交互能力，不属于索引语义。** 把它排除在索引期之外，将其留给未来的「上下文切换预览」功能（章程 §2.2 长期目标），两者互不干扰。

== 7. 后续影响

=== 7.1 对数据模型的要求

§5.3 建议的统一文档模型需扩展：

[source,json]
----
{
  "documentId": "doc-001",
  "path": "docs/architecture.adoc",
  "format": "asciidoc",
  "outgoingLinks": [
    { "target": "standards.adoc#testing", "type": "xref",
      "conditional": false, "line": 42 }
  ],
  "conditionalLinks": [
    { "target": "appendix.adoc", "type": "xref",
      "condition": "backend-html5", "line": 118 }
  ],
  "includes": [ "chapters/part-01.adoc" ],
  "unresolved": [ { "kind": "unresolved-include", "line": 90 } ],
  "contextFingerprint": "sha256:…",
  "parserVersion": "4.2.1"
}
----

=== 7.2 对实现的约束

* 链接解析器必须接受上下文对象作为显式入参，禁止依赖全局可变状态。
* 图谱查询接口需区分「主干边」与「条件边」，不得默认合并。
* 重索引的触发条件是上下文指纹变更或文件内容变更，两者独立。
* `unresolved-include` 必须在 UI 中与 `broken-link` 使用不同标识，避免用户误判为路径写错。
