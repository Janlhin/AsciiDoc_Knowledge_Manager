== 两类规则

[cols="1,2,1",options="header"]
|===
|类别 |判据 |默认严重度

|`broken-xref` 失效 xref
|`xref:` / `<<路径>>` 按下列语义解析后找不到文件；Antora 资源 ID 命中多个同名文件时按「无法判定」处理
|error（歧义为 warning）

|`broken-include` 失效 include / 循环
|`include::` 目标不存在；或全库包含关系形成 A→B→A 的环
|error
|===

== 解析语义（本片的核心契约）

AsciiDoc 的 `xref` 是**文件相对**的（`docs/a.adoc` 里的 `xref:b.adoc` 指 `docs/b.adoc`），按 wikilink 的库根/同名规则去判会验错东西。但本项目预览层把 `href` 交给 Markdown 解析器，用的是**库根相对**。两者不一致时，lint 若只认文件相对，就会出现「lint 说断了、点得开」。

因此契约是「先文件相对，再库根相对」，并保留一条硬边界：

[cols="1,2,1",options="header"]
|===
|目标形态 |解析顺序 |结果

|`#anchor` 纯锚点
|同文档引用，不查文件
|resolved

|`https://…` / `mailto:…`
|外部链接，不检查
|resolved

|`xref:page.adoc#sec`（普通路径）
|① 相对当前文件精确匹配；② 缺扩展名时补 `.adoc` / `.md`；③ 再试库根相对
|命中即 resolved，否则 broken

|`xref:./page.adoc` / `../page.adoc`（显式相对）
|只按文件相对解析，**不回退库根**
|broken 当且仅当真的不存在

|`xref:c:m:page.adoc`、`xref:partial$x.adoc`（Antora 资源 ID / family）
|**有 `antora.yml` 时**按组件/版本/模块/family 精确解析（见第二片）；**无描述符时**按同名文件唯一匹配
|resolved；0 个 → broken；多个 → unresolved

|`include::partials/x.adoc[]`
|文件相对（前导 `/` 为库根），**不做同名回退**
|命中即 resolved，否则 broken

|include 环
|全库图检测，闭环那一行报一次
|error
|===

「unresolved」是刻意的第三种状态：没有 `antora.yml` 时资源 ID 按同名文件近似，多版本组件里省略版本无法判定——报成 broken 会让多组件库满屏误报，报成 resolved 又会漏。面板与 AI 结果里它是 warning，文案按歧义来源写明「匹配到 N 个文件」或「匹配到 N 个组件版本，无法确定」。

== 与既有代码的关系

* `src/core/docsAsCode.ts` — 全部纯函数：`parseXref` / `buildDocIndex` / `resolveXref` / `resolveInclude` / `includeEdges` / `findIncludeCycles`。零 I/O，路径表由调用方给。
* `auditNote` 的 `broken-link` 不再吞掉 `xref` / `xref-short`（此前它们被丢给 wikilink 解析器，Antora 目标必然误报）。两类新检查需要 `AuditEnv.files`；没给就**静默跳过**并在接口注释里写明，因为单篇审计（AI 校对）拿不到全库路径。
* `auditVault` 自动把 `notes` 的路径列表传给每条笔记，并在全库层面追加环告警（环跨文件，无法在单篇里判定）。
* 顺手修掉一个真缺陷：两个 runner 的元数据兜底用的是 `parseNote`（Markdown 解析器），`.adoc` 文件在索引滞后时会被按 Markdown 解析，链接与标题全错。改为 `parseDocument`（按扩展名分派）。
* AI 校对提示词从「六条规则」改为按 `AUDIT_RULE_DOCS` 自适应，新增两类自动进入上下文，不会出现提示词与规则集脱节的第二份文案。

== 第二片：Antora 组件 / 版本（2026-11-15）

`src/core/antora.ts` 全部是纯函数；`docAuditRunner.ts` 承担唯一的不纯步骤——枚举库内所有 `antora.yml` 并读取文本——再把索引经 `AuditEnv.antora` 注入体检引擎。复用依赖树中已有的 `js-yaml@4`（兼容层已授权使用），**零新增依赖**。描述符本身不是 indexable 笔记，不参与体检扫描；读不到或格式不合法的描述符一律跳过，绝不臆造组件。

[cols="1,2,1",options="header"]
|===
|目标形态 |解析规则 |结果

|`2.0@catalog:ROOT:index.adoc`
|按 `version@component:module:path` 精确查资源索引
|命中 → resolved（`via: antora`）；版本不存在 → broken

|`catalog:ROOT:index.adoc`（省略版本）
|优先采用**当前文件所属的版本**，否则仅当该组件只有一个版本
|命中 → resolved；多版本且无当前版本 → unresolved（候选＝版本数）

|`2.0@catalog:ROOT:partial$intro`
|family `partial` → `partials/` 目录；缺扩展名时补 `.adoc` / `.md`
|命中 → resolved

|`ROOT:index.adoc`（两段式）
|第一段不是组件名但确为当前组件的模块时，按 module 解释
|命中 → resolved

|`xref:index.adoc`（纯路径）
|无资源 ID 段，仍按首片「文件相对 → 库根相对」
|与首片完全一致

|无 `antora.yml` 的库
|索引为空，资源 ID 退回唯一同名匹配
|与首片完全一致
|===

语义契约（D-021）：组件版本根＝`antora.yml` 所在目录；`version` 缺省视为无版本组件；只有 `modules/<module>/<family>/...` 下的文件进入索引（`pages`→`page`、`partials`→`partial`、`examples`→`example`、`images`→`image`、`attachments`→`attachment`）；`module` 缺省取当前文件所属模块或 `ROOT`，`family` 缺省 `page`；索引键统一小写比较。有描述符的库中，显式资源 ID **不再同名回退**，查不到即 broken。

真机证据：一次性夹具库含 `catalog/2.0` 与 `catalog/2.1` 两个版本以及库根 `antora-check.adoc`。体检面板恰好 **1 条「2 个组件版本」warning、1 条未知版本 error**，版本限定的有效 xref **0 误报**；`--self-check` 反转大纲期望后仍只有该用例转红。

== 缺口（两片之后仍未做）

. **组件/版本切换 UI 未做**：本片只建立语义层与校验结果，没有产品级的切换视图或发布流程。
. **不校验锚点存在**：`xref:page.adoc#section` 只验证文件，不验证 `#section`（`[[id]]` 尚未进索引）。
. **include 只查环，不设深度阈值**：10 层嵌套不会告警。
. **不展开条件包含**：`ifdef::[]` 内的 include 按普通文本处理（与索引解析器的既有边界一致）。
. **发布前检查 / 按组件导出 / xref 自动修复** 未做。
. **Antora 全语义未覆盖**：`latest` 版本别名、大小写敏感路径、`start_page` / `nav` / `asciidoc.attributes` 均未解析。
