== 版本号五处同步

发版 bump 时，以下五处必须同一版本号（规则沿用 `docs/DISTRIBUTION.adoc`「发布一个新版本」
第 1 步，SemVer 2.0.0）：

1. `package.json` 的 `version`；
2. `package-lock.json`：根 `"version"` 与 `packages[""]` 内 `"version"` 各一处；
3. `src-tauri/tauri.conf.json` 的 `version`；
4. `src-tauri/Cargo.toml` 的 `version`；
5. `src-tauri/Cargo.lock` 中 `name = "adkm"` 条目下的 `version`。

About 页版本取自 `package.json`，不需要另改界面文案。本轮未 bump：五处当前均为 `0.0.1`。

== 构建命令

### A. 只出可执行文件（最快，不打安装包）

```powershell
npx tauri build --no-bundle
```

产物：`src-tauri/target/release/adkm.exe`。用于本机冒烟与排查打包前的 Rust/前端问题。

### B. unsigned NSIS 安装包（本轮验证链路；不带更新签名）

缺私钥时**不要**改仓库里的 `createUpdaterArtifacts: true`（那是正式发版链路的默认值），
改用命令行内联配置覆盖，关掉 updater 产物：

```powershell
npx tauri build --config '{"bundle":{"createUpdaterArtifacts":false}}'
```

产物目录：`src-tauri/target/release/bundle/nsis/`。此包**无 `.sig` 更新签名**，也无
Authenticode 代码签名，仅用于内部验证安装链路，不可对外分发。

### C. signed 安装包（正式发布，当前 blocked）

先设置签名环境变量（私钥内容 / 路径 + 口令，见 `docs/DISTRIBUTION.adoc`），再：

```powershell
$env:TAURI_SIGNING_PRIVATE_KEY = (Get-Content .tauri-keys/adkm.key -Raw)
$env:TAURI_SIGNING_PRIVATE_KEY_PASSWORD = "<密钥密码>"
npm run tauri build
```

产出 `ADKM_<version>_x64-setup.exe` 与同名 `.sig`（minisign 更新签名）。Authenticode
代码签名（防 SmartScreen 黄条）另需购买证书，配置位见 `docs/DISTRIBUTION.adoc` 末节。

== 产物校验

1. **体积与哈希**：记录产物字节数与 SHA256，同版本复构建时比对（Rust release + 前端
   哈希打包，逐字节可复现；跨机器 / 跨工具链产物可能有细微差异，以本机基线为准）。

   ```powershell
   Get-Item src-tauri/target/release/adkm.exe | Select-Object Length
   (Get-FileHash src-tauri/target/release/adkm.exe -Algorithm SHA256).Hash
   (Get-FileHash src-tauri/target/release/bundle/nsis/ADKM_<version>_x64-setup.exe -Algorithm SHA256).Hash
   ```

2. **冒烟**：用内置示例库启动一次，确认窗口能起、库能加载、不白屏：

   ```powershell
   src-tauri/target/release/adkm.exe demo-vault
   ```

   冒烟要点：主界面渲染、文件树列出 `demo-vault/` 笔记、打开一篇 `.md` / `.adoc`
   可读、搜索能命中。本轮未在后台自动化里启动 GUI（见下「未验证项」）。

3. **安装包**：在干净环境（或快照虚拟机）安装一次，确认快捷方式、卸载入口、首次启动
   与 `adkm.exe demo-vault` 一致；安装包内 WebView2 引导行为符合目标系统。

== CHANGELOG 与 TASKS 收口

- `CHANGELOG.adoc`：发布时把「未发布（Unreleased）」节改为目标版本号 + 日期，按
  `=== 新增 / 变更 / 移除` 归类；条目必须写真实产物数字或实测结论，阻塞项如实写阻塞。
- `TASKS.adoc`：发布前确认挂在该版本上的任务全部「完成」，遗留项要么并入本版要么顺延。
- `DECISIONS.adoc`：发版相关取舍（版本号、签名策略、分发渠道）逐条留决策记录。

== 回滚方式

- **未发版**：产物只在本机 `target/` 下，不入库；撤回即删除产物目录，代码回退到上个
  提交即可。
- **已推送包但未公告**：从发布渠道撤下安装包与 `latest.json`；更新链路以
  `latest.json` 为唯一清单，清单下架后旧实例不会拉到该包。
- **已被实例安装**：更新签名是硬门槛——损坏或错误的包签名校验失败、不会被安装；
  回滚靠发布一个版本号相同或更高、内容回退的新包，并在 `latest.json` 指向它。
  私钥丢失 = 永远无法向已装机用户推送更新，`.tauri-keys/` 离线备份是硬前置。

== Blocked（本轮不做、不冒称完成）

- **minisign 更新签名**：私钥与口令不在仓库；本轮产出的 unsigned 包无 `.sig`，不能走
  自动更新链路。
- **Authenticode 代码签名**：证书未购，未配置 `bundle.windows.signCommand`。
- **公开发布与 `latest.json`**：仓库可见性、发布渠道、版本号与公告文案待定。
- **GUI 真机冒烟**：安装、升级、卸载、WebView2 引导未在本轮自动化中执行。
