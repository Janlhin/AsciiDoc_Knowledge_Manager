=== 为什么基线提交不是上游的 SHA

初次推送时，远端拒绝接收，报 `did not receive expected object`。原因是本仓库由浅克隆创建，历史缺少父提交对象，远端无法完成索引。

处理方式是用上游提交的文件树重建一个根提交，得到一条完整、非浅的两提交历史：

. `6e80e93` — 上游快照（根提交，无父）
. 其后各提交 — 本项目改动

两者文件树逐字节一致，因此以 `6e80e93` 为基准执行 `git diff` 得到的差异，与以上游提交为基准完全相同。上游原始 SHA 仍记录在上表，供追溯使用。

=== 上游状态核查

2026-11-13 核对远端 `main` 分支 HEAD 与基线提交一致，确认上游自 2026-07-04 起未产生新提交。

这意味着本仓库与上游之间不存在持续合并关系。若上游在后恢复更新，处理方式见 <<_与上游的关系>>。

== 与上游的关系

本仓库采用**内嵌基线**形态，不是活跃 fork：

. 首个提交为基线提交的完整快照，git 历史自该点起独立。
. 本地**不配置**上游远端，避免残留的跟踪引用干扰完整性检查。需要摘取上游某个提交时，临时添加：

[source,bash]
----
git remote add upstream https://github.com/AlexHercules/geode.git
git fetch upstream main
git cherry-pick <commit>
git remote remove upstream
----

. 不跟随上游的常规提交，不承担上游重构的适配成本。

== 保留的上游能力

=== Obsidian 插件兼容层

`src/compat/` 全部保留，共约 10,397 行。

**保留理由**：该层使本产品能够加载 Obsidian 社区插件与主题，是差异化能力的一部分，不属于待清理的历史包袱。它仅对 Markdown 文件生效；AsciiDoc 文件不经过该层。

=== 样式机制的两个不可动点

以下约束在后续改造中必须持续遵守，原因与许可无关，与技术正确性有关：

. `theme-bridge.css` 与 `export.css` 保持为 CSS，不转 SCSS。
. `:root` 与 `html[data-theme]` 中的调色板字面量保持为 CSS 自定义属性，不转为编译期变量。原因有二：Obsidian 主题在运行时覆盖这些变量；`theme-bridge.css` 头部要求调色板与其逐字同步，变量化后无法用文本检索校验。
